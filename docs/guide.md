# Как пользоваться Claude Bridge

## Подключение

Сначала [установите backend на свой VPS](../README.md#1-установите-backend-на-ubuntu-vps) и выпустите токен устройства. Откройте корень проекта в терминале, скопируйте `desktop/.env.example` в `desktop/.env` и задайте IP или имя VPS, имя пользователя SSH и порт. Первый вход по SSH требует проверки ключа хоста по отпечатку из консоли VPS.

| Что сделать | macOS | Windows |
| --- | --- | --- |
| Скопировать шаблон | `cp desktop/.env.example desktop/.env` | `Copy-Item .\desktop\.env.example .\desktop\.env` |
| Открыть туннель для чата | `./desktop/connect-macos.sh --chat` | `.\desktop\connect-windows.ps1 -Chat` |
| Проверить backend в другом окне | `curl http://127.0.0.1:18765/healthz` | `Invoke-RestMethod http://127.0.0.1:18765/healthz` |
| Подключить рабочий стол XFCE, если он установлен | `./desktop/connect-macos.sh` | `.\desktop\connect-windows.ps1` |

Если удобнее открыть туннель вручную, замените адрес и пользователя в примере на значения из `desktop/.env`:

```sh
ssh -N -T -p 22 -o StrictHostKeyChecking=yes -o ExitOnForwardFailure=yes -o ServerAliveInterval=20 -o ServerAliveCountMax=3 -L 127.0.0.1:18765:127.0.0.1:18765 ubuntu@203.0.113.10
```

1. Установите [VSIX](../artifacts/claude-bridge-0.1.0.vsix) через **Extensions → … → Install from VSIX…**.
2. Откройте панель **Claude Bridge**, нажмите **Подключить** и вставьте значение `token` из команды `sudo /opt/claude-bridge/admin add --account personal --label ИМЯ_УСТРОЙСТВА`, выполненной на VPS.
3. Выберите модель `mock · mock` и отправьте «Привет». Для обычной работы подключите [свой провайдер](providers.md) и выберите его модель из списка.

Подробности по XFCE, RDP и возврату в ту же сессию приведены в [инструкции к рабочему столу](desktop.md).

## Иконки и элементы панели

| Элемент | Что делает |
| --- | --- |
| ![Значок моста](../extension/media/bridge.svg) **Claude Bridge** | Открывает чат в левой панели VS Code. |
| **Точка состояния** | Зелёная означает активное подключение. Жёлтая появляется при подключении и повторной попытке. Красная означает отказ в доступе. Серая появляется, когда устройство нужно подключить. Рядом есть текст состояния. |
| **Диалоги** | Позволяет открыть предыдущий разговор. История хранится по аккаунту. |
| **+** | Создаёт новый диалог. |
| **Модель** | Выбирает, какой модели отправить следующий запрос. |
| **↥** | Добавляет текстовый файл из текущей рабочей папки во вложения. |
| **⌗** | Добавляет выделенный текст из открытого локального редактора. |
| **×** рядом с вложением | Убирает вложение из следующего запроса. |
| **Доступ к рабочей папке** | Разрешает агенту вызывать локальные инструменты в выбранной доверенной папке. Если папок несколько, выберите нужную в списке рядом. |
| **Отправить** | Отправляет текст и очередь вложений. Клавиши — `Cmd+Enter` на Mac и `Ctrl+Enter` на Windows. |
| **Стоп** | Отменяет текущую генерацию и снимает запросы на подтверждение. Уже принятые действия остаются применёнными. |
| **Инструмент · …** | Показывает, какое действие сейчас выполняет агент или какой результат обрабатывает модель. |
| **Применить изменение**, **Создать файл**, **Удалить файл** | Подтверждает конкретную правку после просмотра содержимого в VS Code Diff. |
| **Выполнить** | Запускает показанную команду из указанной папки. |
| **Отклонить** | Отказывает в конкретной правке или команде. |

## Работа с проектом

- Для вопроса о коде откройте локальную папку, установите доверие к ней в VS Code, выберите её в панели и включите **Доступ к рабочей папке**. Например, попросите «Найди, где настраивается HTTP-порт, и объясни, как он передаётся в сервер».
- Для обсуждения одного фрагмента выделите его и нажмите **⌗**, затем отправьте вопрос. Черновые вложения передаются при отправке.
- Для изменения файла дождитесь открытия Diff. Слева показан текущий текст, справа предлагаемая версия. Проверьте правку и выберите действие в панели.
- Для терминала прочтите показанную команду целиком и проверьте её рабочий каталог. После подтверждения вывод появится в терминале Claude Bridge.

Проверить инструменты без платного API можно одним запросом к `mock · mock`:

```text
/mock [{"name":"list_directory"},{"name":"create_file","arguments":{"path":"bridge-test.txt","content":"Claude Bridge test\n"}}]
```

Для нескольких устройств выпускайте по одному токену с одинаковым `--account`. Команда VS Code **Claude Bridge: Отключить устройство** удаляет локальную копию токена. Для блокировки токена на сервере выполните `sudo /opt/claude-bridge/admin revoke ID_УСТРОЙСТВА`.

Если индикатор показывает переподключение, проверьте, что SSH-туннель открыт и `/healthz` отвечает. Для уже работающего SSH-входа по ключу можно указать `claudeBridge.sshTarget` в пользовательских настройках VS Code. Удобно использовать алиас из SSH config, чтобы он включал нестандартный порт. После смены адреса снова подтвердите токен в панели расширения.
